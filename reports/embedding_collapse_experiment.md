## Context

The deliverable is a frozen 32-d embedding (`head.shared` output) consumed by a downstream
deep-kernel-learning GP. It is collapsing: `emb_effective_rank` measures **1.32–2.85 of 32**
against a 15–25 target. A near-scalar embedding makes GP distance degenerate into "difference
in predicted pProp", destroying the posterior-variance signal active learning runs on.

The `w_vic` scan topped out at 9.46 and showed no measurable `goal_metric` cost, but could not
settle the question: one seed, and seed spread (1.32 vs 2.85) exceeded every `w_vic` effect
below 0.1.

This experiment determines what loss configuration prevents collapse, with enough replication
to be believable and enough interaction evidence to decide whether it can be **pinned** in
`sweeps/bayes_v2.yaml` or must be **swept**.

**Scope** (settled with Ethan): loss + regularization — `w_vic`, `vic_gamma`, `weight_decay`,
`dropout`. Head architecture is out of scope (`embed_dim=32` and linear task heads are
deliverable requirements). **Budget** ~60 runs / ~6 h on 3 A6000s (16 min/run), fold 0 unless
stated. **Success bar:** maximise rank subject to no predictive cost; 15–25 is aspirational,
and an honest "unreachable" is an acceptable outcome.

**Results and their reading: `reports/embedding_collapse_results.md` § S1.** The headline is

Two things from S1 that changed the *design* of what follows, and so belong here:

- **The S1 selection rule is defective**, discovered by executing it. It ranks clearing cells on
  the mean of `tanimoto_partial` with no dispersion and no worst-corner condition, and selected

A **randomized complete block design**: every cell on the same seeds `{0,1,2}`, fold 0.

There is deliberately **no separate noise-floor stage**. The error term for a paired contrast is
the *seed × config interaction*, which a single-config seed scan cannot estimate — it measures
σ_seed instead, 4–5× larger and the wrong quantity. An 8×3 RCBD gives **14 residual df** free,
versus 2 df from any isolated pairwise comparison.

**Deliberately absent:** `weight_decay` (P6.3 predicts a null below ~0.1; no `n` in this budget
resolves a null — one `wd=0.1` probe sits in S2), and any `w_vic` < 0.3 (P5 showed it
unresolvable against seed noise; do not re-buy that measurement).

**Why γ=1.0 only at `w_vic=3`.** γ does *not* change the hinge's gradient (`relu(γ−σ)` has slope
−1 for every dim below γ), so it is a **scale target, not a strength knob**. Its real effect is
indirect: the covariance half scales as ~s⁴, so lifting the operating scale 0.5 → 1.0 multiplies
it ~16×. But P6.2 shows the model is already force-starved at γ=0.5 (28/32 dims below target,
trace 5.34 against the 8.0 that "all dims at 0.5" needs). Testing γ=1.0 at low `w_vic` would
read as "γ does nothing" for the wrong reason.

**Why dropout gets two cells.** `_mlp_blocks` appends `Dropout` as the last layer of *every*
hidden block including the bottleneck, and `forward_with_embedding` returns `self.shared(x)` —
so the `z` fed to `variance_covariance_loss` is **post-dropout during training**. With inverted
scaling, `Var(z') = Var(z)/(1−p) + E[z]²·p/(1−p)` while covariance is unchanged. Measured
`mean|dim mean| ≈ 0.4`, so a dead dim (std 0.017) shows an apparent std of ~0.20 at p=0.2 —
inflated ~12× out of its own mean. **Falsifiable prediction: dropout weakens the hinge, making
rank no better and plausibly worse at fixed `w_vic`.** The val-time metric is honest (`eval()`
makes dropout identity), so this corrupts the *loss*, not the measurement. It is also the
strongest argument against pinning `w_vic` while `bayes_v2` sweeps dropout 0.05–0.35.

### Execution

**Drive `train.py` directly, one process per GPU, 3 in flight.** `run_config.py` trains
in-process *sequentially*, so it would serialize each config's seeds — the opposite of what a
screen wants. Driving `train.py` and reading `meta.json` directly also defuses all five known
`run_config` traps at once (stale `already_done` reuse that ignores `val_embeddings.npy`; the
`f{fold}s{seed}` label collision; `final/*_std` conflating folds and seeds). Reserve
`run_config.py --aggregate-only` for the winner's final 5×2, where pooling and wandb are wanted.

**Buckets: human-readable**, `outputs/rank_v1/<cell>/fold{F}_seed{S}`. `config_id` buys nothing
here (it changes the moment `--w-cov` lands) and costs legibility. **The analysis reads
hyperparameters from `meta.json["config"]`, never from the directory name** — so a mislabelled
directory is a caught error, not a silent one.

**Ordering: seed-major** — all 8 cells at seed 0, then seed 1, then seed 2. Stopping early then
leaves a complete unreplicated block rather than three finished cells and five empty ones.

```bash
cd /home/ethan2/finetune_minimol
VENV=/home/ethan2/finetune_minimol/.venv/bin/python
ROOT=outputs/rank_v1
CELLS=(
 "A_base|--w-vic 0   --vic-gamma 0.5"
 "B_w0.3|--w-vic 0.3 --vic-gamma 0.5"
 "C_w1|--w-vic 1     --vic-gamma 0.5"
 "D_w3|--w-vic 3     --vic-gamma 0.5"
 "E_w10|--w-vic 10   --vic-gamma 0.5"
 "F_w3_g1|--w-vic 3  --vic-gamma 1.0"
 "G_w3_drop|--w-vic 3 --vic-gamma 0.5 --dropout 0.2"
 "H_drop|--w-vic 0   --vic-gamma 0.5 --dropout 0.2"
)
for S in 0 1 2; do
  for G in 0 1 2; do
   ( for i in "${!CELLS[@]}"; do
       [ $(( i % 3 )) -eq $G ] || continue
       NAME=${CELLS[$i]%%|*}; FLAGS=${CELLS[$i]#*|}
       OUT=$ROOT/$NAME/fold0_seed$S
       [ -f "$OUT/val_embeddings.npy" ] && continue   # resume on the file already_done forgets
       CUDA_VISIBLE_DEVICES=$G $VENV src/train.py --fold 0 --seed $S $FLAGS \
         --no-wandb --no-save-checkpoint --out $OUT >> /home/ethan2/logs/rank_v1_gpu$G.log 2>&1
     done ) &
  done
  wait                                                 # one complete seed block at a time
done
```

`train.py` has no `--device`; `CUDA_VISIBLE_DEVICES` is the pin. `--no-wandb` throughout —
`meta.json` holds everything.

### `[!]` Pre-registered rules for S2 — WRITTEN 2026-08-19, BEFORE ANY S2 RUN FINISHED

S1's rule was defective and the S1 report says so: it ranked clearing cells on the mean of
`tanimoto_partial` with **no dispersion and no worst-corner condition**, and so selected on a
gap of 0.018 against a per-seed sd of 0.047. The paired `C_w1 − D_w3` differences are
+0.0684 / −0.0312 / +0.0155 (mean +0.0176, sd 0.0498), giving t = 0.61 at n = 3. Resolving that
mean at 95% would need **~36 seeds per cell** — more than this entire experiment's budget. The
repair is not more replicates; it is to stop ranking on an unresolvable mean.

**S2-R1 — the gate.** A cell must still clear all four S1 conditions, recomputed on the S2
design: significant Δlog(rank) vs `A_base`, all seeds same direction, both damage guards,
`tanimoto_partial` above control.

**S2-R2 — the worst-corner condition (new).** `min` over seeds of `emb_effective_rank` must be
**≥ 12**. The threshold is not invented here: **12 is the number S4 already uses** as the point
below which "the loss cannot fix this" fires. A configuration whose worst seed lands in
territory S4 calls unfixable cannot be the configuration S4 pins. On S1's seeds this passes
`D_w3` (min 23.33) and fails `C_w1` (min 5.85); the point of writing it now is that seeds 3 and
4 can overturn either verdict.

**S2-R3 — ranking, with a resolution test.** Among cells passing R1 and R2, rank by
`knn20_jaccard` — the local metric, and the one a GP kernel actually consumes — **but only if
the top two differ by more than `t_crit · σ · √(2/n)` computed on that metric from the same
RCBD.** `tanimoto_partial` is **demoted to a gate only** (R1 condition 4) and is no longer a
ranking metric; the arithmetic above shows ranking on it is not a measurement.

**S2-R4 — the terminal branch.** If R3 cannot resolve the top two, **pin the survivor with the
higher worst-corner rank** and record the global-vs-local disagreement as an open question
**escalated to the DKL project**, not to more fold-0 seeds. This is not a new preference: S4
already says "pin at the value that suffices in the worst corner," written before S1 launched.
"Unresolved here, decided downstream" is a legitimate pre-registered outcome.

### `[!]` What block 2 actually tests — a confound in `F_w3_g1`, not the plan's refinement branch

The plan's refinement branch reads *"stds sit at γ, **rank still low** → covariance binding."*
**That trigger is not met.** `D_w3` reads rank 30.14 / 23.33 / 29.71 — rank is not low, and
there is almost none left to buy. Running `--w-cov` as if the trigger fired would be dishonest.

The real justification comes from S1's own data. `F_w3_g1` raised γ to 1.0 and produced the
highest rank (31.0) with the **lowest** `tanimoto_partial` of the four clearing cells (0.095) —
but γ changes *two* things at once: it multiplies the operating scale (`emb_trace` 34.9 against
`D_w3`'s 9.3) **and**, because the covariance half scales as ~s⁴, it multiplies covariance
pressure ~16×. **F confounds them.** `J_w3_cov16` applies ~16× covariance pressure at γ = 0.5,
so the scale does not move — which separates the two:

| if F's low `tanimoto_partial` was caused by… | then `J_w3_cov16` shows… |
|---|---|
| **covariance pressure** | rank ↑ toward 31, `tanimoto_partial` ↓ toward ~0.10, `emb_trace` stays ~9 |
| **scale inflation alone** | rank ↑, `tanimoto_partial` stays near `D_w3`'s 0.147, `emb_trace` stays ~9 |

`emb_trace` is the column that separates the readings, and it is pre-registered as such.
`I_w3_cov4` is the intermediate rung, so the answer is a dose response rather than one point.
Either outcome is informative: it decides whether rank beyond ~28 is worth buying at all.

### Block 3 — the weight-decay null, and a correction to its own arithmetic

`K_wd0.1` runs at `--w-vic 0` **deliberately**: P6.3 is a claim about the *collapse mechanism*,
and collapse happens at the baseline. If wd were the shrinker, 10× the decay at `w_vic = 0`
must make the collapse worse.

**Correction to the plan's "≈35% shrink".** That is the *un-annealed* figure: P6.3's 4.3% head
shrink assumes full `lr` for all 4,420 steps, and the same paragraph notes "cosine roughly
halves both". So `wd = 0.1` delivers roughly **20%**, not 35% — still a 5× amplification of the
effect P6.3 calls arithmetically inert, which is what makes the probe worth 3 runs.

**Read it as a null probe, and only as that.** No `n` in this budget resolves a null, so a flat
result is weak confirmation of P6.3, not proof. The probe is sharply informative only if it
comes back **positive** — if rank moves at `wd = 0.1`, P6.3's arithmetic missed something and

## `[x]` S2.5 — Does the embedding actually work as a featurizer? (0 GPU-runs, 10 min)

**Added 2026-08-19, after S2, before S3.** S1 and S2 establish that the 32 slots are *occupied*
and that they are occupied by *chemistry* rather than noise or restated pProp. Neither shows
they are **useful**. `vic` is unsupervised: chemical variation irrelevant to AmpC binding
satisfies it exactly as well as variation that matters, so nothing in the loss steers the
recovered dimensions toward relevance.

The sharpest statement of the gap: **a random 32-d projection of ECFP4 bits would score well on
`tanimoto_partial` and `knn20_jaccard`** — it *is* structure — while being no better as a
featurizer than the fingerprints it came from. The structural readout separates "chemistry"
from "restated pProp"; it cannot separate "chemistry" from "useful chemistry".

Run before S3 because it is a **cheap gate on an expensive stage**: minutes of CPU against S3's
12 GPU-runs. It does not invalidate S3's measurements — "does `w_vic=3` survive 40 epochs and
dropout 0.3" is a fair question either way — but it decides whether the answer matters, and
what to do if the pin turns out fragile.

### `[x]` COMPLETE — 2026-08-19, ~10 min, `src/feature_utility.py`

**Results and their reading: `reports/embedding_collapse_results.md` § S2.5.** All three rules
pass at `D_w3`. The headline positive is **U3 by a wide margin** — the fine-tuned 32-d embedding
reaches held-out-cluster kNN Spearman 0.862 against 0.773 for the raw frozen 512-d trunk and
0.673 for ECFP4. The headline complication is that **utility falls monotonically with `w_vic`**
(0.871 → 0.869 → 0.862 → 0.857 across `A_base` → `C_w1` → `D_w3` → `E_w10`): the term
redistributes pProp-relevant information across the space rather than adding any, at a cost of
about 0.009 Spearman. Per the reporting rule above this is **not** applied retroactively to S2's
selection. A defect in U1's own wording was found by executing it and is recorded in the results
file rather than patched.

### Design

Probe a featurization for held-out-**cluster** skill, never held-out molecules: the DKL GP will
be queried on novel chemistry from a generative loop, so a random split would flatter every
featurizer here. Split fold 0's validation clusters 50/50, fit on one half, test on the other,
then swap and average.

| featurization | dim | what it establishes |
|---|---|---|
| embedding, top-*k* PCs, k ∈ {1, 2, 4, 8, 16, 32} | k | **the core curve** — does skill keep climbing past k=2, or do 30 dimensions add nothing? |
| the model's own predicted pProp | 1 | **the floor.** If 32 dims cannot beat their own scalar output, nothing else in this experiment matters |
| raw frozen MiniMol embedding | 512 | the frozen-embedding workflow this repo exists to beat |
| ECFP4 | 2048 | the null featurizer — chemistry with no model in it at all |

Two probes, because they ask different questions. **kNN** (k=20, distance-weighted) tests
whether *distance* in the space is informative, which is what a GP kernel actually consumes and
is therefore the primary. **Ridge** tests linear extractability, which is the property
`head.py`'s linear task heads were chosen to guarantee.

### `[!]` Pre-registered rules — WRITTEN 2026-08-19 BEFORE THE PROBE WAS RUN

Response is **Spearman on the held-out clusters** under the **kNN** probe, at the pinned config
`D_w3`, averaged over both split directions. The error scale is the **sd across the seeds run**.

**U1 — the floor.** `k=32` must exceed the 1-d predicted-pProp baseline by more than that sd.
Failing U1 means the 32-d embedding is not worth exporting over the model's scalar output, and
no amount of rank fixes that.

**U2 — the dimensions earn their place.** `k=32` must exceed `k=2` by more than that sd.
Failing U2 means the rank recovered in S1/S2 is cosmetic for prediction: real chemistry, no
downstream use. The response is **not** more loss tuning — it is to renegotiate `embed_dim`
with the DKL project, or to add an information-bearing supervised auxiliary target.

**U3 — fine-tuning is not destroying information.** `k=32` must not fall below the raw frozen
512-d MiniMol baseline by more than that sd. Failing U3 would be the most important result in
the project and is currently unfalsified.

**Reporting rule.** All three are reported for `A_base`, `C_w1`, `D_w3` and `E_w10`, so the
k-curve's shape can be read against the `w_vic` dose. **This does not become a selection rule
for S2 retroactively** — `D_w3` is already chosen under S2's pre-registered rules, and adopting
a metric after seeing which cell it favours is exactly the defect that sank the S1 rule. If the
probe disagrees with the S2 pin, that is recorded as a finding and settled by a stage designed
for it, not by silently re-ranking.

**Known limitation, stated in advance.** This measures *mean-prediction* utility. Active
learning also needs calibrated uncertainty, and a featurizer could carry little extra signal
about pProp while still giving a GP an honest notion of "far from anything I have seen".
`scalarness` and `knn20_jaccard` speak to that; this probe does not. **Failing U2 is therefore
not proof the extra dimensions are worthless to the DKL project** — it is proof they do not
help predict, which is the weaker and more measurable half.

## `[x]` S2.6 — Does the geometry buy usable *uncertainty*? (0 GPU-runs, ~1 h)

**Added 2026-08-19, after S2.5.** This is the measurement the whole anti-collapse effort rests
on, and it has never been taken. The argument is a four-link chain:

> collapsed embedding → GP distance degenerates into "difference in predicted pProp" →
> posterior variance stops tracking genuine ignorance → active learning has nothing to steer on

Every link is plausible. **None is measured.** S1/S2 established the first link's premise
(`scalarness` 0.960 → 0.283) and S2.5 showed the fix **costs** 0.009 held-out Spearman. This
stage asks what it **buys**. Run before S3 for the same reason S2.5 was: S3 and the sweep both
harden a configuration whose benefit is unverified and whose cost is now measured.

### Design

Same held-out-**cluster** split as S2.5. Fit an **exact GP** (Matern 5/2 + white noise, one
isotropic length-scale, hyperparameters optimised per run) on `n_fit` labelled molecules drawn
from one half's clusters; predict mean **and variance** on the other half. Cells `A_base`,
`C_w1`, `D_w3`, `E_w10`, so the answer can be read against the `w_vic` dose.

**Embeddings are fed raw, not standardised.** Standardising would rescale `A_base`'s ~30
near-dead dimensions to unit variance and inject pure noise into the kernel, making the control
fail for a preprocessing artefact rather than for the pathology under test. "Deploy the frozen
embedding into a GP" means the raw tensor. A z-scored variant is run for `A_base`/`D_w3` only,
as a robustness check.

`n_fit` is deliberately small (~1,000). GPs are O(N³), and early active learning has few labels
anyway — this is the regime the deliverable is actually for.

### `[!]` Pre-registered rules — WRITTEN 2026-08-19 BEFORE THE PROBE WAS RUN

Error scale throughout is the **sd across seeds** of the quantity being tested.

**V1 — the variance is calibrated at all.** At `D_w3`, ρ(posterior std, |actual error|) must be
positive by more than the seed sd. A GP whose variance does not predict its own error is
decoration, and nothing downstream can use it.

**V2 — the variance tracks *novelty*, not just prediction. THIS IS THE ONE THAT MATTERS.**
ρ(posterior std, ECFP-novelty) — where ECFP-novelty is `1 − max Tanimoto to any training
molecule` — must be **higher at `D_w3` than at `A_base`** by more than the pooled seed sd.
Reported beside it, as the failure mode in its own currency: ρ(posterior std, |predicted pProp −
median predicted pProp|). **The pre-announced expectation is that `A_base`'s variance is nearly
a pure function of prediction extremity and blind to structural novelty, and that `D_w3`'s is
not.** If V2 fails, the anti-collapse work has no demonstrated benefit and the 0.009 Spearman is
being paid for nothing.

**V3 — it acquires better.** Simulated batched active learning over the held-out pool: seed
with a random labelled set, acquire by **UCB (mean + 2·std)** in rounds, count cumulative
pProp ≥ 3.5 molecules found. `D_w3`'s UCB curve must beat `A_base`'s UCB curve, and both must
beat random. Greedy-on-mean is reported as the exploitation-only reference.

**What each failure means, stated in advance.**
- **V1 fails** → the GP setup is wrong (kernel, scale, `n_fit`), not the embedding. Fix and re-run.
- **V2 fails** → the central claim of this project is unsupported. Do **not** proceed to S3 or
  the sweep on `w_vic=3`; re-open whether `w_vic` should be 0, and take that question to the DKL
  project with this evidence.
- **V3 fails while V2 passes** → the geometry is honest but acquisition needs a better rule than
  UCB. That is the DKL project's problem, not this one's, and `w_vic=3` still stands.

**V3 is the weakest of the three** and is labelled so before it runs: one acquisition rule, one
pool, one fold, and a surrogate that is already accurate enough that pure exploitation is hard
to beat. Read V1/V2 as the result and V3 as corroboration.

## `[x]` S2.7 — Remove the cause, not the symptom: LayerNorm at the export point (6 runs, ~35 min)

**Added 2026-08-19.** P6.3 named **LayerNorm** as the likely collapse mechanism and then the
experiment spent 39 runs building a penalty to fight it. LayerNorm normalises across the 32
dimensions *within each row*, so one dominant pre-activation divides every other dimension down
— which is exactly the measured baseline std profile (0.934 → 0.017). **`--w-vic` penalises the
symptom; removing the norm removes the cause**, and it was never tested. It should have been
tested before S1.

The stakes are concrete: S2.5 showed `w_vic=3` costs **0.009 held-out Spearman**. If deleting a
LayerNorm recovers the rank for free, that cost disappears and the whole S1/S2 branch becomes a
fallback rather than the plan.

### Implementation

`DualHead(bottleneck_norm=...)`, surfaced as `--bottleneck-norm`. `None` means "same as
`--head-norm`", so **the default is bit-identical to the previous architecture** — verified:
identical module sequence and 1,611,938 params, with `none` dropping exactly the 64 LayerNorm
parameters. The bottleneck is still built by the same `_mlp_blocks` helper as every other
width, just with its own norm argument, so there is no second definition of "a hidden block".

The hidden 1024-wide layers **keep** their norm. The collapse is a property of the exported
32-d tensor; destabilising the whole stack is not part of this test.

> Note this re-hashes every `config_id` again (`run_config.mirror_train_arguments` copies the
> whole parser). Still pre-sweep, so still free — but it is another reason the sweep must not
> be registered until the architecture question closes.

### The cells

A balanced 4 x 3 block reusing S1's runs at seeds 0–2 for the two controls.

| cell | flags | new runs | decides |
|---|---|---|---|
| `A_base` | `--w-vic 0` (LayerNorm on) | 0, reused | the collapse control |
| `D_w3` | `--w-vic 3 --vic-gamma 0.5` | 0, reused | the current pin |
| `L_nonorm` | `--w-vic 0 --bottleneck-norm none` | 3 | **the test.** Does removing the norm fix the collapse on its own? |
| `M_nonorm_w3` | `--w-vic 3 --vic-gamma 0.5 --bottleneck-norm none` | 3 | do the two compose, or is the penalty redundant once the cause is gone? |

### `[!]` Pre-registered rules — WRITTEN 2026-08-19 BEFORE THE RUNS

**N1 — does it fix the collapse?** `L_nonorm` must clear the S2 rule set against `A_base`:
significant Δlog(rank), all seeds the same direction, both damage guards, `tanimoto_partial`
above control, and worst-corner rank ≥ 12.

**N2 — is it free?** `L_nonorm` must not lose held-out-cluster kNN Spearman against `A_base`
(the S2.5 probe, same split, same rules) by more than the seed sd. This is the whole point:
`w_vic=3` costs 0.009, and a fix that costs the same buys nothing.

**N3 — which architecture is pinned.** If N1 and N2 both pass, **`L_nonorm` replaces `D_w3` as
the pinned configuration** and `--w-vic` reverts to its default of 0. If N1 passes and N2 fails,
the two fixes are equivalent in kind and `D_w3` stands on the evidence already gathered. If N1
fails, LayerNorm is exonerated as the mechanism, P6.3's hypothesis is wrong, and `D_w3` stands.

**`M_nonorm_w3` is diagnostic, not a candidate.** It answers whether the penalty still does
anything once the cause is removed. If `M ≈ L`, `w_vic` was only ever undoing LayerNorm.

**Unstated risk, named in advance:** without the norm the bottleneck's scale is unconstrained,
so `emb_trace` may run large or small. S2 established that rank tracks operating scale, so
**`emb_trace` must be read beside every rank number here** — a rank rise that is purely scale
inflation is the `F_w3_g1` result again, and N2 is what catches it.

## Analysis — `src/emb_readout.py` (new)

One CSV row per run: cell, fold, seed, every hyperparameter from `meta.json["config"]`, every
`val/*` from `history[-1]`, plus:

| column | definition |
|---|---|
| `tanimoto_spearman` | ρ(emb_dist, 1−T) — structural information |
| `pred_tanimoto_spearman` | ρ(\|Δpred\|, 1−T) — **the control**, flat at ~0.07 |
| `tanimoto_partial` | ρ of rank-residuals of emb_dist on \|Δpred\| vs rank(1−T) — information *beyond* the prediction |
| `scalarness` | ρ(emb_dist, \|Δpred\|) — the failure mode itself |
| `knn20_jaccard` | mean overlap of each molecule's 20 nearest by ECFP vs by embedding — what a GP kernel actually uses |
| geometry | `eff_rank`, `top1_share`, `trace`, per-dim std percentiles, `n_dims_below_0.1`, `n_dims_below_gamma` |

**Mechanics.** Sample 5,000 molecules per fold **by dataset row id, not position**: sort
`val_indices.npy`, draw with `default_rng(20260818 + fold)`, map back per run via
`np.searchsorted`, and `assert` the run's indices match the reference. Unpack fingerprints with
`np.unpackbits(fp[rows], axis=1)`. Tanimoto by Gram matrix (`inter = B@B.T`); distances by the
`x²+y²−2xy` trick — never an `[n,n,32]` broadcast. **Cache `T` and `rank(1−T)` per fold**, not
per run; `rankdata` over millions of pairs is the expensive step.

**Spearman throughout** — Euclidean-vs-Tanimoto is monotone at best and Tanimoto is heavily
skewed (median 0.127). Report global ρ *and* `knn20_jaccard` (stratification by construction,
no bins, directly interpretable for the DKL consumer); treat disagreement as a finding. **Do not
quote pair-count standard errors** — millions of pairs are not independent; effective n is the
molecule count, and run-to-run variability comes from the seed replicates like every other
metric here.

**Statistics.** Response is **`log(emb_effective_rank)`** at the final epoch — seed effects are
multiplicative (1.32 vs 2.85 at one config) and the target is "3× better", not "+6 units".
Two-way ANOVA cell × seed; σ = √(residual MS), df = 14; contrast vs `A` with `SE = σ√(2/n)`.

At n=3 with pooled σ this detects **+23% rank** (95% CI excluding 0) and has 80% power for
**+35%**. For scale, baseline → `w_vic=0.3` is ≈10σ. **n=3 is ample for every effect that
matters — buy doses, not replicates.**

## Pre-registered decision rules

Written before S1 runs, so the analysis is not post-hoc.

**A cell "clears" iff all four hold:**
1. paired mean Δlog(rank) vs `A` exceeds `2.145 · σ · √(2/n)`;
2. **all n seeds move the same direction** (blocks one chaotic trajectory carrying a cell);
3. both damage guards pass;
4. `tanimoto_partial` increases — *rank without structural information is a noise embedding and
   does not count.*

**Damage guards.** The stated success bar was "no `goal_metric` cost". `goal_metric` cannot
serve as that test: its entire observed spread (0.9598–1.0065) is carried by `ap_uniform` over
~620 positives on one fold, while `pearson_uniform` moves only 0.002 across the same eight runs.
These guards serve the same intent with metrics that can actually detect a cost:

- **Primary:** paired non-inferiority on `pearson_uniform`, margin **0.005** (2.5× its observed
  full spread) — lower 95% bound of paired Δ must exceed −0.005.
- **Secondary:** paired Δ`mse`, upper bound < **+0.010** (5% of 0.185).
- `goal_metric` reported as a **two-sided bound**, never as a claim.

**Best config** = highest `tanimoto_partial` among clearing cells — *not* highest rank. Rank is
the proxy; the readout is the thing.

**Diagnosis table** (per-dim stds and trace dumped for every run):

| observation | conclusion | action |
|---|---|---|
| stds pile up **below** γ | force-limited | raise `w_vic` |
| stds sit **at** γ, rank still low | covariance binding | raise `--w-cov` (or γ) |
| a stable subset stuck near 0.06 at every dose | GELU-dead dims | **architecture**, not loss |

## `[ ]` S4 — Deliverable: `sweeps/bayes_v2.yaml`, decided in advance

1. **Pin `vic_gamma` and `w_cov`** at the winner's values. Neither trades against `goal_metric`
   in a way bayes can read (§9.2 stands), so sweeping them wastes trials.
2. **Pin `w_vic`** iff S3 shows the paired Δlog(rank) at each corner within 2σ of the
   fold-0 / dropout-0 / 20-epoch value.
3. **If unstable, still pin — at the value that suffices in the *worst* corner.** Do **not** add
   `w_vic` as a sweep axis: a bayes run maximizing `goal_metric` drives it to the floor of
   whatever range it is given, so "sweep [floor, ceiling]" is an expensive way to write "pin at
   floor". Delete the yaml's "most important axis in the file" note.
4. **`weight_decay` stays pinned at 0.01**, with the `lr·wd·steps ≈ 2–4%` arithmetic replacing
   the current "least safe change in this file" caveat — that caveat describes a mechanism that
   does not operate at these learning rates.
5. **`dropout`:** if `G`/`H` show it degrades rank at fixed `w_vic`, the yaml must say so and
   either lower its ceiling or record that `w_vic` was pinned at a dropout-robust value. Two
   axes that interact through the loss cannot be documented independently.

**"The loss cannot fix this; the architecture must change"** fires if any of:
- at the strongest dose, stds sit at γ, a stable subset remains near 0.06, and rank plateaus
  **below ~12** — that is the LayerNorm scale budget plus GELU-dead dims, and no loss
  coefficient reaches it;
- rank rises while `tanimoto_partial` stays flat — the term is manufacturing orthogonal noise;
- every clearing cell fails a damage guard — the trade is real and 15–25 is unreachable via the
  loss.

Escalation order if it fires: (a) export pre-GELU or change the activation (kills the dead-dim
mechanism); (b) renegotiate `embed_dim` with the DKL project; (c) add an information-bearing
auxiliary target — a `32 → 2048` ECFP-bit decoder, noting the readout must then move to a
fingerprint family the decoder never saw.

## Unattended execution — OPEN, unanswered

Ethan asked whether this can run to completion after disconnecting from rabelais.

**What survives:** the GPU work. `nohup`-ed processes outlive the SSH session (that is how P4
and P5 ran). A single driver script can run every specified cell, the readout, and the analysis
unattended.

**What does not:** the model. S2's values and S3's chosen config currently require judgment at
the stage boundaries.

The pre-registered rules above are **mechanical by design** — that is what pre-registration is
for — so they *can* be coded, letting the driver select the winner itself. Three options, not
yet chosen:

1. **Code the pre-registered rules** — driver runs S1, computes ANOVA/contrasts/guards, applies
   the rules, launches S2–S3 on its own choice. Fully autonomous, ~6 h, faithful to the design.
   Risk: a bug in the selection logic sends S2–S3 down a wrong branch — though S1's results
   survive regardless and the script logs its reasoning.
2. **S1 only, then stop** — 24 runs + analysis (~2.5 h), results written, halt. Zero wasted
   compute; S2–S3 wait for review.
3. **Fixed grid, no adaptivity** — pre-specify all ~52 cells and run regardless of intermediate
   results. No selection logic to get wrong, but spends runs on axes S1 might have ruled out,
   and S3 pairs against an a-priori config guess rather than the measured winner.

Also undecided: whether an unattended run may edit tracked files (`CLAUDE.md`,
`sweeps/bayes_v2.yaml`) or should write only to `outputs/rank_v1/**` and
`reports/rank_v1_results.md`. **Default assumption until told otherwise: results files only.**
